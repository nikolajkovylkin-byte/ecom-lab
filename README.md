# Ecom Lab — продающий сайт

Стек: React 18 + Vite 5 + Tailwind CSS + lucide-react + framer-motion.

## Запуск локально

```bash
npm install
npm run dev
```

Откроется адрес вида `http://localhost:5173`.

## Сборка

```bash
npm run build
npm run preview
```

## Структура

- `src/data.js` — весь текстовый контент: программа, 5 тарифов (с полной программой для модалок), FAQ
- `src/context/PackageContext.jsx` — состояние выбранного тарифа, общее для карточек, модалки с описанием, квиза и формы заявки
- `src/components/` — секции сайта, каждая отдельным компонентом, подключены по порядку в `src/App.jsx`
- `src/components/AdminReviews.jsx` — закрытая страница модерации отзывов, `/admin/reviews`
- `api/` — serverless-функции (заявки, отзывы, модерация)
- `public/products/` — реальные фото (куртка, джинсы, автор)

## Что нужно настроить, чтобы всё заработало

Сайт технически готов, но **три вещи работают только после настройки переменных окружения** в Vercel. Без них соответствующая часть покажет вежливую ошибку вместо тишины — сайт не сломается, просто эти функции не будут работать, пока не подключишь.

### 1. Заявки на обучение (форма в конце страницы)

Выбери один вариант:

**Telegram-бот (рекомендуется, бесплатно)**
1. В Telegram у `@BotFather` создать бота командой `/newbot` → получишь `TELEGRAM_BOT_TOKEN`
2. Написать своему новому боту любое сообщение (иначе он не сможет писать тебе)
3. Открыть `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, найти `"chat":{"id": ...}` → это `TELEGRAM_CHAT_ID`
4. В Vercel → Settings → Environment Variables добавить оба значения
5. Передеплоить проект

**Formspree (альтернатива, без Telegram, заявки на email)**
1. Зарегистрироваться на [formspree.io](https://formspree.io), создать форму, скопировать endpoint
2. В Vercel → Environment Variables добавить `VITE_FORMSPREE_ENDPOINT` с этим адресом
3. Передеплоить

Код — `api/submit-application.js`.

### 2. Отзывы на сайте (с модерацией)

Отзыв, отправленный через кнопку «Оставить отзыв», не публикуется сразу — сначала попадает «на проверку». Ты одобряешь его на закрытой странице `/admin/reviews`.

1. В Vercel → **Storage** → **Create Database** → **KV**, подключить к проекту (переменные окружения добавятся сами)
2. В Vercel → Environment Variables добавить `ADMIN_TOKEN` — любая длинная случайная строка (20+ символов), это пароль для `/admin/reviews`
3. Передеплоить

Как пользоваться: зайти на `<твой-домен>/admin/reviews`, ввести `ADMIN_TOKEN`, одобрить или отклонить каждый новый отзыв. Если заодно настроен Telegram-бот из пункта 1 — на каждый новый отзыв придёт уведомление с напоминанием зайти и проверить.

Код — `api/reviews.js`, `api/reviews-admin.js`, `api/reviews-moderate.js`.

### 3. Домен

Подключается в последнюю очередь, когда всё остальное уже проверено (см. чек-лист ниже).

## Пошаговый запуск от нуля до рабочего сайта на домене

1. **Локальная проверка.** `npm install`, затем `npm run dev` — убедиться, что сайт открывается и выглядит правильно
2. **GitHub.** Создать новый репозиторий и залить туда весь проект (`git init`, `git add .`, `git commit`, `git push`) — можно приватный
3. **Vercel.** Зарегистрироваться на [vercel.com](https://vercel.com) (можно через GitHub), нажать **Add New → Project**, выбрать этот репозиторий — Vercel сам определит, что это Vite-проект, и задеплоит без доп. настроек
4. **Проверить деплой.** Открыть выданный Vercel адрес (`что-то.vercel.app`) — сайт уже должен работать, кроме формы заявок и отзывов
5. **Настроить переменные окружения** — пункты 1 и 2 выше (Telegram или Formspree, затем KV + ADMIN_TOKEN)
6. **Передеплоить** после добавления каждой переменной (Vercel → Deployments → ⋯ → Redeploy), иначе новые переменные не подхватятся
7. **Проверить всё вживую**: отправить тестовую заявку, оставить тестовый отзыв, зайти на `/admin/reviews` и одобрить его
8. **Домен.** Купить домен (например, на nic.kz — от 3 000–8 000 ₸/год), в Vercel → Settings → Domains добавить его и прописать у регистратора DNS-записи, которые покажет Vercel (обычно 5–30 минут на применение)
9. **Готово.** Сайт работает на своём домене

## Что стоит проверить/заменить перед передачей заказчику

- Ссылки соцсетей в `Footer.jsx` — сейчас `[ССЫЛКА]`
- Фото автора, тарифы, цены, отзывы Алины/Данияра/Айдоса — уже настоящие, менять не нужно
- Фото товаров (hero, Card Lab, «От товара до продажи») — реальные, но это демонстрационные джинсы/куртка для примера карточки, не товары самого курса — это нормально, так и задумано
- Пароль (`ADMIN_TOKEN`) от `/admin/reviews` — храни отдельно от кода, никогда не клади в файлы репозитория

## Важно про безопасность

Все пароли/токены (`ADMIN_TOKEN`, `TELEGRAM_BOT_TOKEN` и т.д.) должны жить **только** в Vercel → Environment Variables — не в коде, не в README, не в переписке, которую могут увидеть посторонние. Если для регистрации домена/Vercel заведена отдельная почта для передачи заказчику — передавай доступ к ней лично (например, через встроенный обмен паролями в браузере или менеджер паролей), а не текстом, который может остаться в истории чатов.
